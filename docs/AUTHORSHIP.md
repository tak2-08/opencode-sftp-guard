## 2. 이 저장소에서 모델이 실제로 한 일

- 브리프(요구사항)를 threat model 과 approval matrix 로 구조화
- OpenCode 1.18.22 의 실제 동작을 조사해 **기본 permission 이 `{"*":"allow"}` 임을 확인**하고,
  그 함정 때문에 승인 게이트를 "실측성 검증" 방식으로 다시 설계
- 코어(런타임 독립) / 오���코드 결합부를 분리해 **Node 테스트 하네스로 실제 SFTP 통신까지 검증** 가능하게 구성
- 테스트 **132개** 작성(단위 99 + in-process SFTP 서버 통합 22 + 설정 fail-closed 11)
- 자기 감사에서 실제 결함 **14건**을 찾아 수정하고 각 항목을 `docs/SECURITY-REVIEW.md` 에 이력으로 남김
- 문서 5종 + `SECURITY.md` 작성

## 3. 모델이 하지 않은 것 (사람의 몫)

- 공개 여부(공개/비공개) 결정 — 사람이 지시했다
- 실제 비밀 값 · 전용 계정명 · 호스트 경로 — **모델이 대신 입력하지 않았고, 코드에서 기본값으로도 넣지 않았다**
  (비밀은 저장소 밖 `~/.config/opencode/sftp-secrets.json` 에만 존재)
- sshd 설정 변경, Docker 네트워크 정책 변경, 실제 배포 — 모델이 하지 않았고 하지 않아야 한다

## 4. 사용자가 알아두어야 할 한계

모델이 이 저장소를 만들면서 **확실하지 않은 것**을 감추지 않고 문서에 그대로 적었다.
게시자가 아니더라도 반드시 읽어야 하는 세 가지:

1. **Bun 런타임에서의 실행은 실측되지 않았다.** 이 환경에 Bun 이 없기 때문이다.
   코어는 런타임 독립 `.mjs` 로 격리했고, 결정적 검증 절차는
   [`SECURITY-REVIEW.md`](SECURITY-REVIEW.md) §6 에 있다. 실측할 때까지 "동작한다" 는 주장이 아니다.
2. **`--auto` 로 실행하면 이 플러그인의 게이트가 우회된다.** 막을 방법이 없다.
   [`README.md`](../README.md) §12 참조.
3. **모델이 approve-all 을 못 켜게 한 것은 브리프와 다른 의도적 판단**이다.
   근거와 되돌리는 방법은 [`README.md`](../README.md) §5.4 에 있다.
